# ClinePass

在提供商设置中选择 **ClinePass**，添加账号的 API Key，再开启号池模式。号池的 **导入 Key** 支持直接粘贴，一行一个 Key，也支持 `名称----Key`，无需 OAuth。默认 Chat 端点为 `https://api.cline.bot/api/v1/chat/completions`；其他受支持的请求协议沿用 Aether 的格式转换。

先关联本地全局模型，再在 **模型映射** 中选择实际发送的 ClinePass 套餐模型名，例如将本地 `deepseek-v4.1-flash` 映射到 `cline-pass/deepseek-v4.1-flash`。模型目录从 `https://models.dev/api.json` 的 `cline-pass` 节点读取，不调用 ClinePass 的通用 `/models` 接口，也不向公共目录发送账号 Key。目录暂不可用时可手动填写带 `cline-pass/` 前缀的完整模型 ID。普通模型编辑只处理模型属性及价格，不重复配置上游模型和渠道商。

号池及提供商详情分别显示 **5h、7d、30d** 的剩余额度与各自重置时间。套餐到期时间单独显示。任一窗口耗尽时，现有“跳过已耗尽账号”规则会排除该账号，重置后恢复调度；额度接口失败或缺失的窗口显示未知。刷新使用 `/users/me/plan` 和 `/users/me/plan/usage-limits`，不发送模型请求。

在 **模型映射** 中为每个上游模型配置 **渠道商筛选**，提供商设置也保留按模型管理筛选规则的入口。先探测模型的可用渠道商，再从列表选择允许与排除项；允许列表可以调整顺序，按顺序优先请求。允许列表留空时使用已探测的渠道商扣除排除项；不能排除全部渠道商。探测最多发送两次小型模型请求，会消耗套餐额度，并检查该模型是否接受筛选参数。模型忽略参数时会显示不支持筛选。配置随当前表单保存后生效，流式请求自动要求上游返回用量。

模型测试默认按映射发送上游模型名；在测试请求体中手动修改 `model` 时使用手动填写的值。额度刷新和模型请求均使用账号 API Key，通过 `Authorization: Bearer <API Key>` 发送，不需要账号密码或 OAuth 配置。密钥导入固定使用 API Key，无需另选 Bearer token。

ClinePass 的默认 Chat 测试请求不设置 `max_tokens`，避免推理模型在过小的输出预算下返回 `empty response content`；手动填写的 token 限制照常发送。同步响应兼容顶层 `choices` 和 `data.choices`，解包后再处理正文、协议转换和用量；流式响应按 SSE 事件处理。

每条使用记录显示缓存写入与缓存读取 token 数；没有写入统计时记为 0，不将缓存未命中当作缓存写入。ClinePass 的实际渠道商从响应路由元数据提取，同步、流式及协议转换请求均保留审计信息。该字段仅在管理员的使用记录、轮询与详情接口返回，普通用户仅看到缓存读写用量。关闭响应体记录不影响渠道商及缓存统计。
