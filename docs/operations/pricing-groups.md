# 分组定价与缓存单价

## 配置步骤

1. 在管理员「模型管理」中配置模型的基础售价。输入、输出、缓存创建、缓存读取使用美元 / 百万 token；按次模型填写美元 / 次。
2. 打开管理员「分组管理」（也可从「模型管理 → 分组管理」进入），启用分组定价，添加分组并设置统一倍率、用户可见性和默认分组。
3. 在分组的调用范围中展开模型，选择允许调用的供应商。总览会列出该组的模型和供应商；同一模型及供应商可以加入多个分组。新分组初始不开放任何模型，需要显式选择供应商。
4. 用户在创建或编辑 API Key 时选择可见分组；管理员可给用户密钥和独立密钥指定任意分组，包括隐藏分组。
5. 用户「模型目录」页选择分组后显示该分组可用模型及售价；模型详情同时显示各个可见分组的价格。管理员模型详情包含隐藏分组价格。

实际扣费 = 模型基础售价 × API Key 的分组倍率。倍率可以为 0，表示免费。

倍率对组内所有模型统一生效。例如 DeepSeek 分组配置 0.1×，并选择供应商 A、B 的 DeepSeek；Claude 分组配置 1.1×，并选择供应商 A 的 Claude。DeepSeek 分组不能调用 Claude 或其他未选中的供应商。API 模型列表、协议转换、渠道重试及会话续接都遵守该分组的调用范围。

缓存创建、读取和一小时缓存创建直接填写单价。已填写的缓存单价不会随着输入单价修改而变化；未填写的字段沿用计费引擎既有的缺省规则。

## 默认行为

分组定价初始关闭，关闭时使用已有计费逻辑。启用后，模型全局基础售价作为销售价格来源，渠道模型价格覆盖、渠道免费标记和上游密钥折扣不再决定用户售价。

未指定分组的旧 API Key 使用当前默认分组。新建 API Key 会保存选择的分组 ID。默认分组必须对用户可见。

隐藏分组不出现在用户可选列表和价格列表中。管理员已分配的隐藏分组仍正常扣费；用户编辑其他密钥设置时会保留该分组。

已有分组缺少 `model_access` 或该字段为 `null` 时允许全部模型和供应商，以保留原有调用行为。开启「仅允许选中的模型和供应商」后按明确的模型与供应商组合限制；空数组表示不允许调用任何模型。该范围与用户及密钥的既有访问限制取交集。

删除或修改分组 ID 前，先给使用该分组的密钥重新分配分组。不存在的分组会拒绝调用，不会自动切换倍率。

每次请求开始时保存分组倍率快照；请求完成、流式结算和使用记录重放使用该快照。管理员修改倍率会影响后续请求。

## 存储与接口

配置保存在已有系统配置 `pricing_groups` 中，API Key 选择保存在 `feature_settings.pricing_group_id` 中，无需数据库结构迁移。

- 管理员：`GET /api/admin/billing/pricing-groups`、`PUT /api/admin/billing/pricing-groups`。
- 管理员模型分组价格：`GET /api/admin/billing/pricing-groups?global_model_id=<模型 ID>`。
- 用户可见分组：`GET /api/users/me/pricing-groups`。
- 模型价格：`GET /api/users/me/available-models?pricing_group_id=<分组 ID>`。
- 用户创建、修改 API Key 的请求可携带顶层 `pricing_group_id`；修改时传 `null` 表示使用当前默认分组。
- 管理员创建、修改独立密钥也可携带顶层 `pricing_group_id`；修改时传 `null` 表示使用当前默认分组。

每组的 `model_access` 使用 `[{"global_model_id":"模型 ID","provider_ids":["供应商 ID"]}]`。服务端校验模型与供应商关联；用户价格响应不返回该内部列表，仅提供分组倍率、可用性及实际售价。

用户通过通用 `feature_settings` 写入隐藏分组 ID 不会改变计费分组；分组选择在服务端独立校验。
